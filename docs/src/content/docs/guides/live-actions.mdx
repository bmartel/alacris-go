Props go down. Actions come back up. Together they close the loop: the page
asks, the server decides, and the answer arrives as a prop write.

```
component emits 'add'  ->  POST /_alacris/live  ->  handler mutates state
                                                 -> sess.Element("todos").Set("items", ...)
                                                 -> SSE frame -> one DOM update
```

No HTML crosses in either direction.

## Declaring one

`On` forwards a `CustomEvent` the component emits to a named server action:

```templ
@ui.TodoList(props).
    ID("todos").
    On(ui.TodoListEventAdd, "add-todo").
    On(ui.TodoListEventToggle, "toggle-todo")
```

That renders `data-ala-on="add:add-todo toggle:toggle-todo"`. The client
attaches one listener per event type to the document — alacris events are
composed and bubbling, so a single listener reaches every element, across shadow
boundaries, including elements added later.

## Handling one

```go
live.On(srv, "add-todo", func(c *live.Ctx, d ui.TodoListAddDetail) error {
    if _, err := list.Add(d.Text); err != nil {
        return nil            // nothing changed; nothing to push
    }
    c.Session.Element("todos").Set("items", list.Items())
    return nil
})
```

`live.On` is generic: the event detail is decoded into the type parameter
before your handler runs, and `ui.TodoListAddDetail` is the struct the
generator wrote from the component's `@fires` tag. Rename the field in the
component and this stops compiling — which is the point.

The untyped form is there when you want the raw payload:

```go
srv.On("add-todo", func(c *live.Ctx) error {
    var d ui.TodoListAddDetail
    if err := c.Bind(&d); err != nil {
        return err
    }
    ...
})
```

## Per-session handlers

A handler registered on a session takes precedence over the server-wide one and
can close over that page's state:

```go
sess.On("set-filter", func(c *live.Ctx) error {
    var d ui.TodoListFilterDetail
    if err := c.Bind(&d); err != nil {
        return err
    }
    c.Session.Set(filterKey{}, d.Filter)
    c.Session.Element("todos").Set("filter", d.Filter)
    return nil
})
```

Use it for anything that belongs to one page — a filter, a selection, a
wizard step. Server-wide handlers are for changes everyone shares.

## What the context carries

```go
type Ctx struct {
    Session *Session          // the page it came from
    Action  string            // the name you declared
    Element string            // the id of the element that emitted it
    Detail  json.RawMessage   // the CustomEvent detail, still encoded
    Request *http.Request     // headers, cookies, the request context
}
```

`c.Handle()` is shorthand for `c.Session.Element(c.Element)`, which is usually
what you want:

```go
live.On(srv, "greet", func(c *live.Ctx, d ui.UserCardGreetDetail) error {
    c.Handle().Set("greeted", true)   // patch whatever emitted the event
    return nil
})
```

## Errors

Returning an error logs it and answers `500`. It does **not** reach the browser,
and that is deliberate: what a user should see is a patch, sent from the
handler, in whatever terms the page already understands.

```go
live.On(srv, "add-todo", func(c *live.Ctx, d ui.TodoListAddDetail) error {
    if _, err := list.Add(d.Text); err != nil {
        // Say so in the page's own vocabulary rather than leaking an error.
        c.Session.Element("todos").Set("error", "A todo needs some text.")
        return nil
    }
    ...
})
```

## Treat the detail as input

<Aside type="danger" title="A component emits what it says it emits; a console can emit anything">
  The payload arrives from a browser, which means it arrives from whoever is
  using that browser. Binding is strict — unknown fields are rejected — the body
  is size-capped, and cross-origin posts are refused. None of that validates
  your domain rules.

  ```go
  live.On(srv, "set-filter", func(c *live.Ctx, d ui.TodoListFilterDetail) error {
      switch d.Filter {
      case "all", "active", "done":
      default:
          return fmt.Errorf("unknown filter %q", d.Filter)
      }
      ...
  })
  ```
</Aside>

## Keeping the names honest

Both halves of an action are strings, so put them in one place:

```go
const (
    actionAdd    = "add-todo"
    actionToggle = "toggle-todo"
)
```

An action nobody handles is logged as a warning and answered `404`, rather than
being silently dropped — a rename that only happened on one side is otherwise
very hard to find.

## When not to use this

If a change is entirely the browser's business — a disclosure toggle, a hover
state, a local draft — leave it in the component. Signals already handle it,
and a round trip makes it worse. The example app's counter keeps its own state
for exactly this reason and only tells the server what it settled on.
