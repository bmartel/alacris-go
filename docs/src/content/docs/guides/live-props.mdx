A prop is a signal. That is the whole basis of this layer: when the server
changes something, it does not render a fragment and swap it in — it writes
**one property**, which wakes **one binding**, which updates **one DOM node**.

## Setting it up

<Steps>

1. **Create a server** and mount it.

   ```go
   srv := live.New()
   defer srv.Close()

   mux := http.NewServeMux()
   live.Mount(mux, alacris.DefaultBase, srv)
   ```

   `Mount` registers the runtime, the live client, and the two endpoints. Doing
   it by hand is fine; this only exists so the three cannot drift apart.

2. **Mint a session per page render** and put its page id in the page. The
   capability is a cookie the call sets; see
   [Sessions](/alacris-go/guides/sessions/#the-capability-is-a-cookie).

   ```go
   func (a *app) index(w http.ResponseWriter, r *http.Request) {
       // Sets the cookie that authorises this browser, so it has to run
       // before anything is written to w.
       sess := a.live.NewSession(w, r)
       sess.OnOpen(func(s *live.Session) { a.push(s) })

       cfg := alacris.Config{
           Modules: []string{"/web/components.js"},
           UI:      true,
           Live:    true,
           Page:    sess.ID(),
       }
       // ... render the page with cfg
   }
   ```

3. **Give the elements you will patch an id.** A patch addresses an element by
   its `id`, and generated wrappers return an `*Element`, so:

   ```templ
   @components.Board(props).ID("board")
   ```

4. **Patch.**

   ```go
   sess.Element("board").Set("items", list.Items())
   ```

</Steps>

## The API

```go
h := sess.Element("board")

h.Set("items", list.Items())        // a component prop
h.SetAttr("data-state", "ready")    // an ordinary attribute; nil removes it
h.Class("is-busy", true)            // toggle a class
h.SetHTML(ctx, "empty", tmpl)       // replace the children of one slot
h.Props(map[string]any{...})        // several props, one frame
```

`Set` takes the **JavaScript** prop name from `define()` — `maxCount`, not
`max-count` — because it writes the DOM property rather than the attribute.
That is also why values need no encoding: they are JSON on the wire and become
real JavaScript values on arrival.

<Aside type="note" title="Why the property and not the attribute">
  Writing the property sets the signal directly, and it sidesteps the boolean
  removal problem that makes attributes awkward. Values assigned before an
  element upgrades are replayed by `define()`'s constructor, so a patch that
  arrives early is not lost.
</Aside>

## Batching

Every `Send` is a frame. Wrap a group so the browser applies them together and
the page does not paint half an update:

```go
sess.Batch(func() {
    sess.Element("board").Set("items", items)
    sess.Element("board").Set("columns", columns)
})
```

## Sending to everyone

```go
srv.Broadcast(live.Prop("ticker", "price", 42.5))

for _, s := range srv.Sessions() {
    s.Element("board").Set("items", items)   // when each page needs different data
}
```

This is what makes two open tabs agree without either of them polling.

## When props are the wrong tool

`SetHTML` replaces the light-DOM children assigned to one slot with markup the
server rendered:

```go
h.SetHTML(ctx, ui.ChipSlotDefault, chipText("4 left"))
```

Reach for it when the server genuinely owns the markup — a rendered document, a
chunk of a report. For anything a component already models as a prop, a prop is
smaller, does not touch the DOM the user is interacting with, and keeps
rendering where the component put it.

<Aside type="caution" title="A named slot needs an element">
  Bare text cannot be assigned to a named slot; it lands in the default one.
  Render an element around it — the client logs a warning if you do not.
</Aside>

## What this costs

Sessions live in memory, so the server is stateful and needs session affinity
behind a load balancer. See [Deploying](/alacris-go/guides/deploying/). The
first two layers of this library have no dependency on any of it.
